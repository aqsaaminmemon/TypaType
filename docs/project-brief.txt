1. Project objective
Build TypaType, a small C++ desktop typing game with a cute, friendly violet interface.
Use the approved design as the visual reference. The application should feature:
- A full-width typing board.
- Difficulty and duration selectors above the board.
- A small white cartoon kitten between the selectors.
- Three difficulty levels.
- Timed rounds containing a fixed number of random words.
- Clear typing feedback and correction rules.
- WPM and accuracy results.
- Locally saved personal progress.
- Light/dark themes, adjustable text size, and sound controls.
Implement the actual game logic, graphics, persistence, and results. Any sample scores or presentation controls in the design preview must be replaced with real application behaviour.
2. Technology stack
Use:
- C++17 or newer for application logic.
- Qt 6 Widgets for the desktop interface.
- QPainter for the typing display, highlights, caret, and progress chart.
- Qt SVG for the kitten artwork and small icons.
- Qt Multimedia / QSoundEffect for short sound effects.
- CMake for building the application.
Keep game logic separate from interface rendering.
The relevant graphics tools are documented in Qt Widgets, QPainter, Qt SVG, and QSoundEffect.

13. Timer behaviour
Before the round starts:
- Show the selected duration.
- Show “Start typing to begin.”
- Keep the countdown stopped.
Start the timer on the first printable character entered, including an incorrect character.
Do not start it from empty Enter, empty Backspace, clicking the board, or pressing modifier keys.
Use a monotonic clock for timing.
When the timer expires:
1. Stop accepting typing input.
2. Freeze the final round state.
3. Calculate WPM and accuracy.
4. Save the completed round once.
5. Immediately show results.
Keep timer expiry as the finish condition. If the player submits all allotted words early, do not generate more words. Allow only corrections permitted by the Backspace rules until the timer expires.
14. Enter behaviour
Enter advances to the next word even when the current word contains mistakes.
When Enter submits a nonempty word:
- Compare the typed text with its target.
- Lock it if it is correct.
- Keep it editable if it is incorrect.
- Advance to the next word.
Ignore Enter on an empty word.
Enter is the word-advance key. Space must not silently submit a word; a space entered inside the current word is an extra character and should be marked accordingly.
After the last target word is submitted, do not create another target word.
15. Backspace behaviour
Implement these rules:
- Within the active word, Backspace deletes the previous character.
- From an empty active word, Backspace may return to the immediately preceding word if that word is editable.
- Correct submitted words are locked.
- Backspace cannot edit a locked word.
- Backspace cannot cross a locked word to reach an earlier mistake.
When returning to an editable previous word, place the cursor at its end and delete its last character with that Backspace press.
Preserve later typed words when revisiting an earlier editable word.
Enter after editing a revisited word advances to the following word, retaining any existing input there.
A corrected word becomes locked when submitted again with Enter.
Example:
Target: cat dog moon
Typed:  cat dpg
The player can return to correct dpg, but cannot edit the correctly submitted cat.
If a correct word lies between the current position and an earlier mistake, it forms a boundary that Backspace cannot cross.
Apply the same rule after the final word: Backspace may return from the end position only when the immediately preceding submitted word is incorrect.
16. Typing feedback

- Upcoming characters: readable muted text.
- Correct characters: violet accent.
- Incorrect characters: coral-red with a subtle background highlight.
- Extra characters: clearly marked as errors.
- Missing characters in submitted words: visibly marked as missing.
- Current position: a clear caret.
Use exact matching for punctuation and numbers.
Keep incorrect submitted words visibly marked until corrected.
Do not use harsh flashing, screen shaking, or loud error sounds.
Use a readable monospace font for typing text and a clean interface font for labels.
Wrap text within the full-width board. Keep the current word visible as the player advances or revisits previous input.
17. Restart and navigation
Restart must:
- Discard the current attempt.
- Preserve the selected difficulty and duration.
- Generate a fresh word set with the correct count.
- Reset the timer and all counters.
- Return to the waiting state.
Do not save restarted attempts.
Changing difficulty or duration also discards an active attempt and prepares a fresh round.
Leaving Play during an active round abandons that attempt. Returning to Play prepares a fresh waiting round.
Do not add pause-and-resume functionality.
If typing focus is lost while the player remains on Play, the timer continues.
18. WPM calculation
Use the five-character word convention:
WPM = (credited characters / 5) / duration in minutes
For completed rounds, use the selected duration: 15, 30, or 60 seconds.
Credited characters are:
- Characters matching their expected positions in the final stored input.
- Plus one separator for each submitted word whose final text exactly matches its target.
Include correct characters in the active unfinished word when time expires.
Do not credit incorrect, extra, missing, or erased characters.
Calculate WPM from the final input state so repeatedly typing and deleting characters does not inflate speed.
Keep full precision internally and display one decimal place.
Do not apply difficulty multipliers.
19. Accuracy calculation
Use:
Accuracy = correct character attempts / total character attempts × 100
Each printable character insertion counts as an attempt.
An attempt is correct only when the inserted character matches the expected character at that position.
Include letters, punctuation, and numbers.
Do not count Enter, Backspace, modifier keys, navigation keys, or interface shortcuts as character attempts.
Correcting an error must not erase that mistake from the statistics.
For example, ten wrong character attempts remain ten wrong attempts even after the player deletes or fixes them.
Missing characters should be highlighted visually, but must not create fictional keystroke attempts.
Handle zero attempts safely.
Display accuracy to one decimal place.

25. Architecture
Keep the project simple, with clear responsibilities:
- MainWindow: navigation and application layout.
- PlayPage: controls, kitten, typing board, and Restart.
- TypingWidget: keyboard input and character rendering.
- GameSession: state, timing, locking rules, and scoring counters.
- WordGenerator: vocabulary, randomisation, difficulty, and exact word counts.
- ResultsPage: results and Play Again.
- ProgressPage: comparisons, history, and chart.
- HistoryStore: saved completed rounds.
- SettingsStore: saved preferences.
- ThemeManager: colours and styling.
- MascotWidget: face, paws, expressions, and gestures.
- SoundManager: playback and volume.
Use clear session states:
Ready
Running
Completed
Keep input and scoring logic independent of painting.
